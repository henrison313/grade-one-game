### 2.1 填空题格式不统一 ⚠️ **最常见问题**

**问题描述**：
填空题组件使用 `{{___}}` 作为空白标记，但部分关卡数据使用 ` ___ ` 格式。

**导致后果**：
- 题目无法正常解析
- 输入框不显示
- 用户无法输入答案

**已修正文件**：
- `level-1-1-enhanced.data.ts`
- `level-2-1.data.ts`
- `level-4-1.data.ts`
- `level-4-2.data.ts`
- `level-4-3.data.ts`
- `level-h1.data.ts`
- `level-h2.data.ts`

**教训**：
> ⚠️ 新关卡开发前，先检查填空题格式是否使用 `{{___}}`

### 2.2 填空题答案判断逻辑错误

**问题描述**：
单空白题有多个可接受答案（如 `answer: ['4', '四']`），代码错误地认为需要填入所有答案。

**原逻辑（错误）**：
```typescript
// 错误：认为需要填入所有答案
isCorrect = userAnswers.length === correctAnswers.length && ...
```

**修正后（正确）**：
```typescript
// 正确：单空白时，任意一个答案即可
if (blankCount === 1) {
  isCorrect = correctAnswers.some(ans => ans.trim().toLowerCase() === userAnswers[0]);
}
```

**教训**：
> ⚠️ 理解 `answer: string | string[]` 的语义：
> - 单空白 + 数组答案 = "任意一个都可接受"
> - 多空白 + 数组答案 = "每个位置对应一个答案"

---

### 2.3 拖拽题只显示文字标签

**问题描述**：
拖拽题的 `DragItem` 有 `shape` 属性，但组件只显示 `item.name` 文字，不显示图形。

**原因**：
组件未处理 `shape` 属性，只渲染文字。

**修正方案**：
```typescript
// 新增 ShapeSVG 组件
const ShapeSVG: React.FC<{ shape: string; size: number }> = ({ shape, size }) => {
  // 根据 shape 类型渲染对应 SVG
};

// 渲染时判断
{item.shape ? <ShapeSVG shape={item.shape} size={40} /> : <ItemText>{item.name}</ItemText>}
```

**教训**：
> ⚠️ 检查题目数据是否有图形属性（shape），如有则渲染 SVG 而非文字

---

### 2.4 新题型类型定义遗漏

**问题描述**：
新增 SHAPE_COMPOSE 题型时，忘记在 Question 联合类型中添加。

**导致后果**：
TypeScript 类型检查报错，需要手动添加。

**正确做法**：
```typescript
// question.types.ts 需修改两处：
// 1. QuestionType 枚举
export enum QuestionType {
  SHAPE_COMPOSE = 'shape_compose', // 新增
}

// 2. Question 联合类型
export type Question = 
  | ChoiceQuestionData
  | ... 
  | ShapeComposeQuestionData; // 新增
```

**教训**：
> ⚠️ 新增题型时，同时更新枚举和联合类型

---

### 2.5 React 拖拽事件难以自动化测试

**问题描述**：
使用 CDP 浏览器自动化测试拖拽功能时，无法完整模拟 React 的拖拽事件。

**原因**：
- CDP 的 `/click` 只触发 DOM click，不触发 dragstart/dragend
- React 使用 SyntheticEvent，需要特殊方式触发

**解决方案**：
手动验证拖拽功能，自动化测试只验证 DOM 结构。

**教训**：
> ⚠️ 拖拽类题型需手动验证交互功能

---

### 2.6 TypeScript 未使用变量报错

**问题描述**：
开发过程中声明了未使用的变量，导致编译失败。

**示例**：
- `ItemCountBadge` styled component 未使用
- `allItemsPlaced` 变量未使用
- `e` 参数未使用

**教训**：
> ⚠️ 开发完成后运行 `npm run build` 验证编译，删除未使用代码

### 3.2 题目数据改造清单

| 检查项 | 标准 | 修正方法 |
|--------|------|----------|
| 填空题空白标记 | 使用 `{{___}}` | 替换 ` ___ ` → `{{___}}` |
| 多空白答案 | 数组形式，每个元素对应一个空白 | `answer: ['答案1', '答案2']` |
| 单空白多答案 | 数组形式，表示"任意可接受" | `answer: ['4', '四']` |

```typescript

  type: QuestionType.FILL_BLANK,

  explanation: '...',

// ✅ 正确的多空白格式
{
  type: QuestionType.FILL_BLANK,
  question: '第一空{{___}}，第二空{{___}}',  // 多个 {{___}}

{
  type: QuestionType.SHAPE_COMPOSE,
```
